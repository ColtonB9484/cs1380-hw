Why use malloc for the log instead of int log[100]; when the shift might record 8 readings or 800
	Because malloc can dynamically allocate memory at runtime. If int log[100]; was used, it would load at compile time.
	If we use the standard int log[100] it must be hard-coded to a specific value. Malloc makes it so we can get the amount
	ob memory we need while the program is urnning.

What does malloc return on failure? Why must you check before you write through the pointer?
	malloc returns a NULL pointer on failiure. We should check before we write to the pionter because writing to a NULL pointer will crash the program

After make_log returns, who owns that memory, and when does it go away if you never call free?
	The program now owns that memory aftermake_log. Specifically the int array that is being initialized.
	If the program never calls free(); then there may be memory leaks.

How does calloc(n, sizeof(int)) differ from malloc(n * sizeof(int)); in what you can assume about the bytes?
	calloc initializes all bytes to zero while malloc does not initialize the array with any values. 

Why does free_log take int ** instead of int *?
	Because it takes a pointer to the memory block to deallocate the memory. This deallocates all the memory that was previossly allocated with malloc or calloc

If you alloc inside a function and return without free and without handling the pointer bacl to the caller, what happened to that block?
	You could get a dangling pointer or a memmory leak. The memory would then be allocated, but impossible to reach.
