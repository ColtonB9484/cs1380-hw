In the worst case, why must find_code look at every cell?
	Because the picture's order cannot be changed, and the picture numbers are
	not sorted there is not a way to search efficiently. We must look at every
	element within the array to determine if a number is not there.

Why is COLS part of the parameter type pic[][COLS], while the number of rows is a separate argument?
	

What does the array store, and where does the printed glyph(such as # or ' ') come frome?
	The array stores int values. The printed glyphs come from a conditional
	statement that checks what number an element within the array is. If it is
	1, it prints '#', if it is 0 it prints '.', everything else prints '?'

If set_cell is given row == nrows, why must it refuse the write?
	because array index starts at 0, if row == nrows, it is outside the bounds
	of the array. Rows must be greater than 0 and less than (nrows - 1)

Row-major order means the scan finishes a row before it starts the next. What is the flat index of pic[2][3] when COLS is 5?
	the flat index is (row * COLS + col)= (2 * 5 + 3)= 13
