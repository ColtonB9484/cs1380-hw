Why is log = realloc(log, new_bytes); dangerous if realloc returns NULL?
	Because it could remove the original pointer when realloc fails. This would mean that we could not access the data from after the block of memory begins.

After a successfull realloc that moves the block, what must you assume about the old address?
	The old address is assumed to be the same. So we should free the memory to avoid a memory leak.

Name one difference between a leak, a use-after-free, and a doule free?
	A leak is when allocated memory is not freed, which leads to wasted memory.
	A double free is when the same block of memory is freed more than once.

After free_log &log, why is log[0] = 68; undefined behavior even if it someimtes works?
	log[0] = 68; is undefined behavior because the array log is now dangling a pointer.

When is calloc a better first allocation than malloc? When is realloc the tool instead of allocating a brand-new array and copying by hand?
	calloc is better if values must be assigned to 0 at the allocation time. Realloc is the tool instead
	of allocating a brand-new array when we are appending values, or adding a few values at a time

Why commit a woring make_log / print_log before you add realloc, instead of one giant commit at the end?
	To make sure that there is a starting baseline for functionality before reallocating dedicated memory space. 
	realloc would be useles if there wasn't a working malloc or calloc to begin with
